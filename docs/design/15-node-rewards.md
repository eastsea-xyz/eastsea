# 15. 노드 보상: 켜 두면 바로 받는다, 한 사람은 16분의 1까지 (2026-09-28)

사용자 결정(2026-09-28): "발행 전 16명을 기다리는" 규칙과 "적립 후 분배"는 초기 참여자가 이해하기 어렵고 빈 땅에서 동기가 없다. 대신 **켜 둔 Mac이 바로 나눠 갖되, 한 운영자는 16분의 1까지**로 한다. 이 문서는 [12-launch-plan.md](12-launch-plan.md)의 "발행 시작"과 "반감기 시계" 결정을 대체한다.

## 한 문장

> 블록 보상은 지금 켜져 있는 Mac들이 한 시간마다 나눠 받는다. 한 운영자는 16분의 1까지만 받고, 남는 몫은 발행되지 않는다. 사람이 16명 모이면 보상 전부가 나뉜다.

## 규칙

| 항목 | 규칙 |
|---|---|
| 블록 발행량 | 지금과 같다: 블록당 1 AETH, 약 1년(31,536,000블록)마다 반감. 시계는 메인넷 높이 0부터 |
| 나누는 단위 | 에포크(3,600블록, 약 1시간) |
| 두 몫 | 각 블록 발행량의 **절반은 노드 몫**, **절반은 증명 몫** |
| 노드 몫을 받는 사람 | 그 에포크에 살아 있다는 신호(비콘)를 보낸 **등록된 Mac의 운영자**. 운영자는 Mac을 등록한 지갑 주소 |
| 노드 몫 크기 | 에포크 노드 몫 × min(1/N, 1/16). N은 그 에포크에 신호를 보낸 서로 다른 운영자 수. 운영자의 Mac이 여러 대여도 합쳐서 이 한도 |
| 남는 노드 몫 | 발행하지 않는다(찍지 않는다) |
| 증명 몫 | 블록을 증명한 사람에게 간다(증명 시장). 단 증명자는 **등록된 Mac의 운영자**여야 하고, 한 운영자가 한 에포크에 받는 증명 발행량도 그 에포크 증명 몫의 1/16까지. 넘는 몫은 발행하지 않는다. 수수료 에스크로는 상한 없이 증명자에게 |
| 지급 | 다음 에포크 첫 블록이 운영자 주소 잔액에 바로 더한다. 청구 거래가 필요 없다 |

- **운영자 N명이 모였을 때**

  | N | 한 사람 몫 | 전체 중 나뉘는 몫 |
  |---|---|---|
  | 1 | 1/16 | 1/16 |
  | 4 | 1/16 | 4/16 |
  | 16 이상 | 1/N | 전부 |

## 16분의 1인지 어떻게 아나

- **체인이 센다.** 등록 레지스트리에 Mac마다 운영자 주소와 마지막 신호 에포크가 있다. 에포크가 끝나면 모든 노드가 같은 상태에서 N을 세고 같은 몫을 계산한다. 누구의 서명이나 서버도 필요 없고, 합의 규칙이라 모든 노드가 같은 값을 낸다.
- **누구나 확인한다.** 레지스트리는 공개 상태다. 앱, 탐색기, RPC(`aether_candidates`)로 N과 각 운영자의 몫을 볼 수 있다.
- **한계도 적는다.**
  - 운영자는 지갑 주소 단위다. 한 사람이 지갑 두 개로 Mac 두 대를 등록하면 운영자 둘로 센다.
  - 대신 등록은 DeviceCheck로 **Mac 한 대에 한 번**이라, 16분의 1을 k번 받으려면 실제 Mac k대가 필요하다.
  - 창업자도 같은 규칙이다. 창업자가 받는 양은 가진 Mac 수에 묶이고, 운영자가 16명 이상이면 전체 중 자기 Mac 비율만큼이다.

## 초기 참여자가 알게 하기

보상이 있다는 것을 모르면 동기가 되지 않는다. 가치나 수익 약속 없이, 규칙과 실제로 받은 양을 보여 준다.

| 어디 | 무엇 |
|---|---|
| 앱 Network 화면: 보상 카드 | "이 Mac은 보상을 받고 있습니다. 지난 1시간 +x AETH, 지금까지 y AETH. 운영자 N명 · 한 사람 최대 1/16 · 16명이 모이면 전부 분배" |
| 앱 활동 목록 | 에포크마다 "노드 보상 +x AETH" |
| 알림 | 첫 보상을 받았을 때 한 번 |
| 투표 노드 초대 창, 첫 실행 동의 창 | 규칙 문장(위 "한 문장")으로 교체 |
| 공개 README | "How mainnet will launch" 섹션을 이 규칙으로 교체 |
| 공개 네트워크 화면 | 운영자 수 N, 이번 에포크 분배율 |

- 모든 곳에 같은 문장을 쓴다.
- 가격, 수익률, "지금 들어오면 유리" 같은 표현은 쓰지 않는다([legal-review-2026.md](../research/legal-review-2026.md)).

## 이전 규칙과 비교

| | 16명 전 발행 없음(이전) | 적립 후 분배(검토) | 이 규칙 |
|---|---|---|---|
| 첫날 참여자가 받는 것 | 없음 | 잠긴 숫자 | 잔액이 바로 늘어남 |
| 창업자 초기 몫 | 0 | 1/16까지 | Mac 수 × 1/16까지 |
| 설명 | 쉬움 | 어려움 | 쉬움 |
| 사람이 모일 동기 | 순위뿐 | 있음 | 있음: 모일수록 전체가 커짐 |

## 구현 순서

1. 실행 계층(`aether-execution`): 에포크 끝 분배, 증명 발행 상한, 증명자 자격(등록 운영자). 증명 프로그램(guest)도 같은 규칙으로 다시 빌드한다.
2. 메인넷은 제네시스부터 이 규칙이다(업그레이드 불필요).
3. 시험: 유닛 테스트 → 운영자 1, 4, 20명 개발망에서 에포크별 분배 확인 → 테스트넷 적용 여부는 증명 프로그램 교체 부담을 보고 정한다(테스트넷은 지금 규칙으로 두고 개발망에서 충분히 검증하는 쪽이 기본).
4. 앱: 보상 카드, 활동 항목, 첫 보상 알림, 문장 교체(동의 창, 초대 창, README).
