# 24. 스스로 회복하는 노드와 지갑 (2026-09-29)

## 원칙
> 앱은 한 번 배포되면 우리가 손댈 수 없다. **사람이 개입하지 않아도** 노드와 지갑이 스스로 정상으로 돌아와야 한다. 회복할 수 없는 경우에도 사용자가 할 일을 한 문장으로 보여 주고, 그동안 지갑은 다른 노드로 계속 동작한다. 이것은 메인넷 출시 조건이다.

계기: 2026-09-29 11:13 시스템 디스크가 가득 차자 앱 노드의 데이터베이스(redb)가 한 번 쓰기 실패한 뒤 "다시 열어야 함" 상태에 빠졌고, 노드는 같은 블록을 288번 재시도하며 멈춰 있었다. 앱은 "끊김"만 표시했다.

## 하지 않는 것
- 원격으로 사용자의 앱·노드를 조작하는 기능(원격 재시작, 원격 설정). 공격 표적이 되고 우리가 책임을 지게 된다.
- 개인 데이터를 보내는 오류 보고. 보고가 필요하면 사용자가 직접 복사해 보내는 요약만.

## 시험 (출시 조건)
디스크 가득 참(ENOSPC 주입), 데이터베이스 손상, 증명기 강제 종료, 메모리 한도 초과, 노드 멈춤, 네트워크 전체 끊김 뒤 재연결, 업그레이드 직후 반복 종료, **모든 검증자 동시 재시작**(정전·재부팅: 서로를 기다리다 영원히 멈추면 안 된다). 각각 사람 없이 정상으로 돌아오는지 자동 테스트로 확인한다.

## 구현 (2026-09-29, 층 1·2·3)

**노드 안 (층 1)** — `store.rs`·`follow.rs`·`chain.rs`·`application.rs`:
- 저장소 오류를 종류별로 가린다: `StoreError::Io`(디스크 — 닫았다 다시 열면 나음), `Unreadable`(깨진 파일 — 다시 받아야 함), `Corrupt`/`RootMismatch`(내용 불일치), `Reopening`(다시 여는 중). 디스크 오류는 `Recovery::reopen`이 백오프(1초에서 60초, 기본 8회 ≈ 3분)로 데이터베이스를 다시 열고, 열린 뒤 실제 쓰기 한 번(검증 쓰기)으로 "아직 디스크가 찼는지"까지 확인한다. 낫지 않으면 프로세스는 **종료 코드 4**(저장소)로 끝난다. `AETHER_STORE_RECOVERY=<ms>,<횟수>`(숨김)가 시험용 값을 정한다.
- 팔로워가 확정 블록을 저장하다 실패하면(`follow`의 `recover`) 검증점으로 되돌리고(`rollback`, 재실행 없이 fsync된 마지막 검증점) 다시 받아 온다. 검증자 경로는 확정 블록을 올리던 바로 그 자리에서 회복한다(`chain.heal_store`): marshal이 이 호출을 기다리는 동안 이 노드의 합의는 잠시 멈추고, 디스크가 다시 쓰기를 받으면 커밋을 다시 한다. 블록이 디스크에 닿기 전에는 절대 확인(ack)하지 않는다 — 확인하지 않은 블록은 재시작 뒤 다시 전달된다(at-least-once). 저장소 오류를 "블록이 실행되지 않았다"고 적던 2026-09-29의 로그는 사라졌다.
- 시작할 때 무결성 검사(`follow::open_store`): 데이터베이스가 열리는지, 검증점과 그 블록 행이 읽히는지. 안 되면 `state.redb`(검증자면 마샬 파티션까지)를 `corrupt-<시각>/`으로 **옆으로 옮기고**(지우지 않는다; 키는 그대로) 새로 시작하며, 기존 빠른 따라잡기(스냅샷 점프)로 다시 받는다. 디스크 오류는 옮기지 않고 시작 실패 — 재시작이 같은 파일을 다시 시도하게 한다.
- 종료 코드: 3 업그레이드 필요, **4 저장소**, 5 증명 검증기 없음.

**앱 감시 (층 2·4)** — `NodeWatchdog.swift`(판정만 — 순수 로직, 단독 시험 가능)과 `NodeController`:
- 노드가 스스로 죽으면 백오프(1초, 2초, 4초… 최대 60초)로 다시 시작한다.
- 10분에 네 번째 종료면 재시작을 멈추고 마지막 실패의 종류(디스크 가득·데이터베이스·메모리·네트워크)로 **한 문장**을 보여 준다. 종류는 종료 코드와 `node.log` 끝부분으로 가린다.
- 네트워크 높이는 오르는데 내 노드가 60초 제자리면(노드가 켜져 있을 때) 재시작한다. 멈춤 판정은 회복 후 진행이 있어야 다시 센다(재시작 순환 없음).
- 새 바이너리가 시작 60초 안에 세 번 연속 죽으면 `Helpers/aether.prev`(업데이트할 때 보존)로 되돌리고 "업데이트 뒤 노드가 시작되지 않아 이전 버전으로 되돌렸습니다"를 보여 준다.

**지갑 (층 3)**: 노드가 죽는 순간 `useLocalNode(nil)` — 이미 있던 원격 노드 폴백이 즉시 켜진다(바뀐 것 없음, 확인만).

**시험**: `crates/node/tests/selfheal.rs`(디스크 가득 1회 → 재시작 없이 회복, 낫지 않는 디스크 → 실제 바이너리가 종료 코드 4, 깨진/잘린 데이터베이스 → 옆으로 옮기고 스냅샷 점프로 복구·키 보존, 네트워크 단절 → 회복 후 따라잡기), `store.rs` 단위 시험(다시 열기·분류), `apps/wallet/Tests/watchdog`(감시 판정). 증명기 강제 종료와 메모리 한도는 자원-한도 작업(prover)과 함께 남아 있다.

## 구현 2부 (2026-09-29, 레드팀 #5·#4·#19·#2·#1·#3·#12·#14·17·#7·#9·#16·#20)

**노드 안 (`crates/node`)**:
- **#5 키는 절대 자동 교체 안 함**: `supervisor.rs`·`candidate.rs`·`main.rs` — 등록된 신원의 검증자 키나 노드 계정 키가 없거나 깨지면 새 신원을 만들지 않는다. 데이터 디렉터리의 형제 파일 `node.identity`에 원래 공개 신원을 남겨 **디렉터리 전체가 사라져도** 첫 설치로 오인하지 않는다. `aether run`은 그 Mac을 `Role::Keyless` 팔로워로 돌리고(투표도 후보도 하지 않음), `candidate-info`는 **종료 코드 6**으로 답해 앱이 백업 복구를 안내한다. 비밀 파일은 동기화한 임시 파일로 준비하고, 최초 키는 기존 경로를 절대 덮지 않는 원자 생성으로 쓴다.
- **#4 세 저장소 분리 진단·투표 저널 보존**: `follow.rs`·`engine.rs`·`supervisor.rs` — 손상 복구는 상태 DB·블록 아카이브만 `corrupt-<시각>/`으로 옮기고 `{prefix}-consensus*` 투표 저널은 절대 건드리지 않는다. 엔진은 투표를 시작하기 전에 `vote-epoch-<번호>.seen`을 영속화한다. 확정 블록이 하나도 없는 상태에서도 이 표식 뒤 저널이 사라지면 **종료 코드 8**로 투표를 거부한다. supervisor는 `no-vote` 파일에 위원회 라운드를 적어 **그 라운드가 끝날 때까지** 팔로워로만 돈다. 다음 라운드의 share는 새 저널과 함께 오므로 거기서 다시 투표한다.
- **#19 세대별 설치**: `supervisor.rs` — 인계(network.json·share)를 `<data>/gen/<round>/`에 먼저 쓰고 `.installed` 표식을 붙인다. 기존 검증자 자식을 멈춘 뒤 share → `network.json`(역할 판정 포인터) 순으로 활성화한다. 도중에 죽은 실행은 다음 자식을 시작하기 전에 표식을 보고 같은 자리를 멱등하게 마친다(`finish_incomplete`). 완료할 수 없으면 투표 자식을 시작하지 않는다. 퇴장 멤버의 share는 설치·재개 모두에서 지운다. 오래된 세대는 정리.
- **#2 멈춤과 진행의 분리**: `chain.rs`·`follow.rs`·`store.rs`·`rpc.rs` — 높이 외에 활동 계수(`tick()`: 확정 시도마다, 상류가 답할 때마다, 스냅샷 청크마다, 저장소 재오픈 시도마다)와 단계 표식(`set_stage`: "snapshot"·"storage", 라운드마다 초기화)을 센다. `aether_status`가 `activity`·`stage`로 알려 주고, 앱 감시는 **활동이 오르는 얼어 붙은 높이는 멈춤이 아니라 진행**으로 판정한다.

**스키마 버전 (`crates/node/src/store.rs`)** — 데이터베이스가 자기 레이아웃을 기록하고, 읽을 수 없는 새 레이아웃은 절대 손대지 않는다:

- `min_read_version`이 이 바이너리보다 높으면(앱이 크래시 뒤 `aether.prev`로 되돌린 경우) 새 오류 `StoreError::TooNew`로 **단 한 번의 쓰기도 하기 전에** 거부한다. 이것은 손상이 아니다(`follow::is_corruption`에 넣지 않았다): `corrupt-*`로 옮기지도, 지우지도, 처음부터 다시 받지도 않는다 — 온전한 최신 데이터를 파괴하는 길이므로. `follow::open_store`와 `main.rs`(팔로워·검증자 두 경로 모두)는 이 거부를 받아 기존 **종료 코드 3**(업그레이드 필요)으로 끝낸다. supervisor는 그 코드를 받아 재시작하지 않는다(2부 #1의 이미 있던 규칙), 앱은 이미 있던 "업데이트 필요" 처리로 새 서명 릴리스를 설치한다 — 병렬 메커니즘은 없다.
- 기록된 버전이 낮으면 등록된 마이그레이션 단계를 순서대로 실행한다. 각 서브스텝은 "표식(진행 중) + 데이터" 한 트랜잭션이고 멱등하며, 단계가 끝나면 "표식(완료) + 새 버전 스탬프" 한 트랜잭션이다. 중간에 죽은 실행(프로세스 사망, 커밋 중 ENOSPC 포함)은 항상 기록된 서브스텝 경계에 남아 다음 open이 정확히 거기서 재개한다. 긴 마이그레이션은 서브스텝마다 `chain::tick()`을 세어 높이가 얼어 붙어도 멈춤이 아니라 진행으로 읽힌다(#2).

## 구현 3부 #6·#10 (2026-10-03, 레드팀 #6 시계 점프 · #10 잘못된 위치 실행)

**시계 (#6)** — `Clock.swift`(새 파일: `Clock` 프로토콜·`MonotonicInstant`·`UptimeClock`), `NodeWatchdog.swift`·`NodeController.swift`·`UpdateTracker.swift`:
- 앱의 모든 **지속 시간 판정** — 멈춤 시계(60초), 충돌 창(600초), 빠른 죽음(60초), 후보 재확인(60초), 투표 상태 갱신 스로틀(10초) — 을 단조 시계로 옮겼다. `MonotonicInstant`는 값 타입 래퍼라 `Date`를 단조 자리에 넘기면 **컴파일이 안 된다**(시험 파일이 컴파일되는 것 자체가 그 보증이다). 사람이 읽거나 재시작을 넘어야 하는 값만 `Date`에 남는다.
- 단조 시계로 `DispatchTime.now().uptimeNanoseconds`를 골랐다. Darwin의 `CLOCK_MONOTONIC`은 **잠자는 동안도 전진**해서 잠에서 깨어난 뒤 wake 알림을 놓치면 8시간짜리 거짓 멈춤이 된다(=#6이 막으려는 바로 그 사고). `mach_absolute_time` 계열(`DispatchTime`·`systemUptime`)은 깨어 있는 동안에만 전진한다: 잠자기 자체는 멈춤으로 보이지 않고, 뒤로도 가지 않는다. 정수 나노초라 macOS·iOS 모두에서 같은 의미다. 기존 sleep/wake 무효화(#9)는 그대로 남아 실제 깨어남에서는 측정을 다시 시작하고, 이 시계는 **wake 알림을 잃은 경우까지** 무해하게 만든다.
- 벽시계 점프가 재시작을 만들거나 숨일 수 없음을 시험으로 증명한다: 58초 얼어 붙은 뒤 "+2시간 점프"(수동 변경·NTP step·DST)를 관측에 반영하지 않는 단조 폴은 여전히 기다리고, 60초의 진짜 깨어 있던 시간만 재시작한다. 충돌 창·빠른 죽음 스트릭도 단조 거리만 센다.
- `UpdateTracker`의 영속 시각(`startedAt`·`nextRetryAt`)은 재시작을 넘어야 해서 벽시계일 수밖에 없다 — 대신 **강건하게** 만들었다: 우리가 쓸 수 있는 가장 먼 미래는 최대 백오프(6시간)이므로, 그보다 먼 영속 시각은 시계가 틀리던 때의 산물이다. init에서 now로 클램프하고, 세션 중 시계가 뒤로 점프해 nextRetryAt이 6시간+ 미래가 되면 즉시 due로 판정한다(시도 횟수는 영속되므로 타이트 루프가 되지 않는다). 건강 확인 창은 startedAt이 미래면 `min(startedAt, now)`부터 잰다 — 조기 발화도, 영원한 미발화도 없다.

**위치 (#10)** — `InstallLocation.swift`(새 파일), `NodeController.swift`·`AetherWalletApp.swift`·`ProverMenu.swift`·`SimpleDashboard.swift`:
- 런치 시 번들 경로와 볼륨 읽기 전용 플래그로 실행 위치를 판정한다(순수 함수, 규칙은 한 곳에 명시): (1) App Translocation 경로 → 안 됨, (2) 읽기 전용 볼륨(마운트된 DMG·잠긴 디스크) → 안 됨, (3) `/DerivedData/`·`/build/` 개발 빌드 → 됨(우리가 직접 빌드·실행하는 자리; 허위 경고 금지), (4) `/Applications`·`~/Applications`(하위 폴더 포함, 경로 구분자 경계 검사) → 됨, (5) 나머지(Downloads·Desktop·Documents·`/Volumes/…`) → 안 됨. 볼륨 플래그를 읽을 수 없으면 쓰기 가능으로 취급한다(fail-open: 제대로 설치된 앱을 허위로 재촉하지 않는다).
- 안 되는 위치에서는: **노드가 시작하지 않고**(`start()` 가드), **login item을 등록하지 않는다**(`startAtLogin` setter 가드 + AppDelegate의 기본 등록 스킵 — "이미 적용함" 표시도 남기지 않아 올바른 폴더로 옮긴 뒤 첫 실행에 기본값이 다시 적용된다), **명령줄 도구를 설치하지 않는다**(사라질 번들로의 심볼릭 링크 방지). 사이드바와 메뉴 막대 패널에 한 문장("EastSea를 응용 프로그램 폴더로 옮긴 뒤 실행해 주세요." / 영문)과 Finder에서 보여주는 버튼을 둔다. **지갑의 읽기 전용 뷰는 결코 차단하지 않는다** — 노드만 로컬에서 안 돌 뿐 지갑은 원격 검증자 폴백(층 3)으로 그대로 동작한다. 서명·번들 ID·Sparkle·appcast는 전혀 바꾸지 않았다.
