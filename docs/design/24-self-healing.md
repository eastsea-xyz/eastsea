# 24. 스스로 회복하는 노드와 지갑 (2026-09-29)

## 원칙
> 앱은 한 번 배포되면 우리가 손댈 수 없다. **사람이 개입하지 않아도** 노드와 지갑이 스스로 정상으로 돌아와야 한다. 회복할 수 없는 경우에도 사용자가 할 일을 한 문장으로 보여 주고, 그동안 지갑은 다른 노드로 계속 동작한다. 이것은 메인넷 출시 조건이다.

계기: 2026-09-29 11:13 시스템 디스크가 가득 차자 앱 노드의 데이터베이스(redb)가 한 번 쓰기 실패한 뒤 "다시 열어야 함" 상태에 빠졌고, 노드는 같은 블록을 288번 재시도하며 멈춰 있었다. 앱은 "끊김"만 표시했다.

## 층

| 층 | 무엇을 | 어떻게 |
|---|---|---|
| 1. 노드 안 | 저장소 오류 | 데이터베이스를 닫고 다시 연다(백오프). 안 되면 종료 코드로 끝내 바깥이 재시작하게 한다. 같은 오류에서 무한 반복하지 않는다 |
| | 데이터 손상 | 시작할 때 무결성을 확인하고, 손상되면 옆으로 옮겨 두고 스냅샷 점프(빠른 따라잡기)로 새로 받는다. 키 파일은 절대 지우지 않는다 |
| | 자원 고갈 | 디스크 여유 5GB 미만이면 기록 쓰기·증명을 멈추고 알린다. 메모리 압박·스왑 과다면 증명을 멈춘다. 증명기가 메모리 한도를 넘으면 종료 후 백오프 |
| | 네트워크 | 피어를 모두 잃으면 DHT·릴레이·내장 시드로 다시 찾는다. 오래 뒤처지면 스냅샷 점프 |
| 2. 앱(감시) | 노드 종료 | 자동 재시작(백오프). 10분에 3번 넘게 죽으면 멈추고 원인을 보여 준다 |
| | 노드 멈춤 | 네트워크 높이는 오르는데 내 노드가 60초 넘게 제자리면 재시작 |
| | 업그레이드 실패 | 새 노드 바이너리가 시작하자마자 계속 죽으면 이전 바이너리로 되돌린다(앱 번들에 둘 다 둔다) |
| 3. 지갑 | 내 노드가 없을 때 | 다른 노드(팔로워·검증자)로 읽고 보낸다. 모든 답은 인증서·증명으로 검증하므로 안전하다 |
| 4. 사용자에게 | 회복 불가 | "디스크 공간을 10GB 비워 주세요"처럼 할 일 한 문장. 기술 용어·로그 경로를 앞세우지 않는다 |

## 하지 않는 것
- 원격으로 사용자의 앱·노드를 조작하는 기능(원격 재시작, 원격 설정). 공격 표적이 되고 우리가 책임을 지게 된다.
- 개인 데이터를 보내는 오류 보고. 보고가 필요하면 사용자가 직접 복사해 보내는 요약만.

## 시험 (출시 조건)
디스크 가득 참(ENOSPC 주입), 데이터베이스 손상, 증명기 강제 종료, 메모리 한도 초과, 노드 멈춤, 네트워크 전체 끊김 뒤 재연결, 업그레이드 직후 반복 종료, **모든 검증자 동시 재시작**(정전·재부팅: 서로를 기다리다 영원히 멈추면 안 된다). 각각 사람 없이 정상으로 돌아오는지 자동 테스트로 확인한다.

## 구현 (2026-09-29, 층 1·2·3)

**노드 안 (층 1)** — `store.rs`·`follow.rs`·`chain.rs`·`application.rs`:
- 저장소 오류를 종류별로 가린다: `StoreError::Io`(디스크 — 닫았다 다시 열면 나음), `Unreadable`(깨진 파일 — 다시 받아야 함), `Corrupt`/`RootMismatch`(내용 불일치), `Reopening`(다시 여는 중). 디스크 오류는 `Recovery::reopen`이 백오프(1초에서 60초, 기본 8회 ≈ 3분)로 데이터베이스를 다시 열고, 열린 뒤 실제 쓰기 한 번(검증 쓰기)으로 "아직 디스크가 찼는지"까지 확인한다. 낫지 않으면 프로세스는 **종료 코드 4**(저장소)로 끝난다. `AETHER_STORE_RECOVERY=<ms>,<횟수>`(숨김)가 시험용 값을 정한다.
- 팔로워가 확정 블록을 저장하다 실패하면(`follow`의 `recover`) 검증점으로 되돌리고(`rollback`, 재실행 없이 fsync된 마지막 검증점) 다시 받아 온다. 검증자 경로는 확정 블록을 올리던 바로 그 자리에서 회복한다(`chain.heal_store`): marshal이 이 호출을 기다리는 동안 이 노드의 합의는 잠시 멈추고, 디스크가 다시 쓰기를 받으면 커밋을 다시 한다. 블록이 디스크에 닿기 전에는 절대 확인(ack)하지 않는다 — 확인하지 않은 블록은 재시작 뒤 다시 전달된다(at-least-once). 저장소 오류를 "블록이 실행되지 않았다"고 적던 2026-09-29의 로그는 사라졌다.
- 시작할 때 무결성 검사(`follow::open_store`): 데이터베이스가 열리는지, 검증점과 그 블록 행이 읽히는지. 안 되면 `state.redb`(검증자면 마샬 파티션까지)를 `corrupt-<시각>/`으로 **옆으로 옮기고**(지우지 않는다; 키는 그대로) 새로 시작하며, 기존 빠른 따라잡기(스냅샷 점프)로 다시 받는다. 디스크 오류는 옮기지 않고 시작 실패 — 재시작이 같은 파일을 다시 시도하게 한다.
- 종료 코드: 3 업그레이드 필요, **4 저장소**, 5 증명 검증기 없음.

**앱 감시 (층 2·4)** — `NodeWatchdog.swift`(판정만 — 순수 로직, 단독 시험 가능)과 `NodeController`:
- 노드가 스스로 죽으면 백오프(1초, 2초, 4초… 최대 60초)로 다시 시작한다.
- 10분에 네 번째 종료면 재시작을 멈추고 마지막 실패의 종류(디스크 가득·데이터베이스·메모리·네트워크)로 **한 문장**을 보여 준다. 종류는 종료 코드와 `node.log` 끝부분으로 가린다.
- 네트워크 높이는 오르는데 내 노드가 60초 제자리면(노드가 켜져 있을 때) 재시작한다. 멈춤 판정은 회복 후 진행이 있어야 다시 센다(재시작 순환 없음).
- 새 바이너리가 시작 60초 안에 세 번 연속 죽으면 `Helpers/aether.prev`(업데이트할 때 보존)로 되돌리고 "업데이트 뒤 노드가 시작되지 않아 이전 버전으로 되돌렸습니다"를 보여 준다.

**지갑 (층 3)**: 노드가 죽는 순간 `useLocalNode(nil)` — 이미 있던 원격 노드 폴백이 즉시 켜진다(바뀐 것 없음, 확인만).

**시험**: `crates/node/tests/selfheal.rs`(디스크 가득 1회 → 재시작 없이 회복, 낫지 않는 디스크 → 실제 바이너리가 종료 코드 4, 깨진/잘린 데이터베이스 → 옆으로 옮기고 스냅샷 점프로 복구·키 보존, 네트워크 단절 → 회복 후 따라잡기), `store.rs` 단위 시험(다시 열기·분류), `apps/wallet/Tests/watchdog`(감시 판정). 증명기 강제 종료와 메모리 한도는 자원-한도 작업(prover)과 함께 남아 있다.
