# 25. Base USDC 비서 용돈 계정 — 로컬 구현 (2026-09-30)

근거: [달러 통제 레드팀](../research/redteam-dollar-control-2026-09-29.md), [소비자 전략 레드팀](../research/redteam-strategy-2026-09-29.md), [지갑 설계](09-wallet.md). 이 구현은 로컬 검증용이다. Base나 Aether 테스트넷·메인넷에 배포하지 않았고 실자금을 취급하지 않았다.

## 소비자에게 할 수 있는 정확한 약속

사용자가 승인한 P-256 소유자 키로 계정의 정책과 자금 이동을 통제한다. 비서의 별도 세션 키는 미리 등록한 수취인에게만, 지정한 USDC 주소의 `transfer(address,uint256)`로만 지불할 수 있다. 계약은 6자리 소수의 최소 단위로 건별 한도와 UTC 날짜 경계에 걸친 지출을 상태에 기록하며, 소유자는 세션을 즉시 철회할 수 있다. 코드는 배포 후 바꿀 수 없고 관리자 키가 없다. 소유자 키는 교체·철회할 수 있고 독립 복구 키의 48시간 지연 복구가 있다.

이는 **허용 범위 안의 구매가 정당하거나 유익하다는 보장이 아니다.** 외부 입력에 속은 비서는 허용된 수취인에게 허용된 한도를 모두 쓸 수 있다. Secure Enclave는 키 반출을 어렵게 하지만 소유자 작업의 인증은 Touch ID **또는 Mac 로그인 암호**이며, 비서 결제마다 사람 승인을 뜻하지 않는다. 구매 내용 확인, 확정된 영수증, 환불·분쟁 접수, 이상 지출 알림과 손실 책임은 아직 제품으로 구현되지 않았다. USDC 발행사는 주소 동결·일시 정지·계약 변경 권한을 유지한다. 블랙리스트에 오른 계정의 USDC는 소유자 교체나 복구로 풀리지 않는다. Base의 가용성과 수수료, 선택한 번들러·대납자의 운영에도 의존한다.

## 계약과 서명

- `contracts/base/AllowanceAccount.sol`은 생성자에서 USDC 주소, ERC-4337 v0.7 EntryPoint 주소, 소유자 원시 P-256 공개키 `(x,y)`를 고정한다. EIP-7702 위임이나 `EastSeaAccount.sol`의 `onlySelf` 계정 전제를 가져오지 않는다. 토큰과 EntryPoint 주소는 변경할 수 없으므로 실제 배포 전에 Base의 정확한 주소와 코드 해시를 재확인해야 한다.
- CryptoKit 원시 서명 `r||s`를 사용한다. 서명자는 P-256 차수의 절반보다 큰 `s`를 `n-s`로 정규화해야 한다. 계약은 높은 `s`, 범위 밖의 `r/s`, 곡선 밖 공개키를 거부한다. WebAuthn의 `authenticatorData`·출처·사용자 확인을 검증하는 패스키 경로가 아니다.
- 직접 소유자 실행은 `SHA-256(abi.encode(OWNER_TAG, chainId, account, ownerNonce, expiry, to, value, keccak256(data)))`에 서명한다. ERC-4337 `validateUserOp`은 EntryPoint만 호출할 수 있으며 `executeFromEntryPoint` 호출, 별도의 `userOpNonce`, 만료, `userOpHash`와 체인·계정 도메인을 검사한다. 서명 형식은 `abi.encode(uint64 expiry, bytes32 r, bytes32 s)`다. 배포 및 EntryPoint 예치·번들러 통합은 아직 없다.
- Base의 `0x100` P-256 프리컴파일을 우선 사용한다. 없는 로컬 EVM에서는 Solidity 검증으로 폴백한다. 로컬 폴백은 가스가 비싸고, 실제 배포 전에 선택한 Base 환경의 프리컴파일 동작·가스·서명 벡터를 재검증해야 한다.
- 세션 서명도 체인·계정·고유 세션 ID·논스·만료·정확한 토큰 호출 바이트에 묶인다. 호출 데이터 길이는 정확히 68바이트이고 함수 선택자는 USDC `transfer`뿐이다. 실제 수취인·금액을 디코딩해 허용 목록과 한도를 확인하고, 토큰 호출이 실패하면 지출·논스 갱신도 되돌린다. `approve`, 임의 계약 호출, `transferFrom`, `transferWithAuthorization`은 세션 경로에서 거부한다.
- 하루 한도는 현재 UTC 날짜와 직전 날짜의 지출 합계에 적용한다. 이 방식은 날짜 경계에서 보수적으로 지출을 제한한다. 정확한 이동 24시간 한도와 다르므로 앱은 남은 한도를 같은 규칙으로 표시해야 한다.
- ERC-1271은 제공하지 않는다. USDC의 EIP-3009 `transferWithAuthorization`이 읽기 전용 서명 검증만 호출하면 계정은 누적 일일 지출을 기록할 수 없다. x402에는 상태를 변경하는 계정 `transfer` 경로를 수용하는 결제 대행자 또는 별도 검증된 위임 경로가 필요하다.

## 자금·복구·가스 흐름

로컬에서 정의한 충전 흐름은 **계정 배포 → 별도 기기·보관 장소의 독립 복구 키 등록 → 복구 리허설 → `fund(amount)`로 USDC `approve`/`transferFrom`** 순서다. `fund`는 유효한 독립 복구 키가 없으면 실패한다. ERC-20을 주소에 직접 보내는 행위까지 계약이 막을 수는 없다. 현재 Base용 앱 UI·RPC·충전 연결은 없으므로 앱은 실제 충전 기능과 주소 노출을 열어서는 안 된다. 구현 시 복구 설정과 리허설 확인 전에는 충전 버튼·입금 주소를 노출하지 않아야 한다.

복구 키는 서명된 교체 제안을 내고 48시간 뒤 누구나 완료할 수 있다. 기존 소유자는 대기 중 제안을 취소할 수 있다. 완료 또는 소유자 교체는 이전 세션을 모두 무효화한다. 탈취된 소유자 키가 복구 대기 중 취소하거나 자금을 옮길 수 있으므로 알림·대응 절차가 필요하다. 독립 복구 키 자체의 분실, 기기 탈취, 재설정도 실제 기기로 리허설해야 한다.

| 작업 | ETH 가스 지불자 | 대납 실패 시 경로 |
|---|---|---|
| 계정 배포와 첫 복구 키 설정 | 배포자/릴레이어 또는 EntryPoint에 ETH를 예치한 대납자 | 배포자 ETH 충전 후 재시도 |
| 소유자 정책 변경·세션 철회·복구 제안·완료 | 직접 호출 릴레이어 또는 4337 대납자 | 릴레이어 ETH 충전. 긴급 철회용 별도 예비 경로 필요 |
| 비서의 USDC `transfer` | `sessionExecute` 제출 릴레이어 | 릴레이어 ETH 충전 후 재시도 |
| 향후 x402 정산 | 선택한 facilitator/릴레이어 | 대납 정책 또는 ETH 충전 경로 확인 전 결제 불가 |

USDC 잔액이 ETH 가스비를 자동으로 내지는 않는다. 테스트 코인 보상도 이 비용의 재원으로 계산하지 않는다. `validateUserOp`의 `missingAccountFunds`는 계정이 보유한 ETH로 EntryPoint를 충전할 수 있을 때만 동작한다.

## 레드팀 필수 수정 6개 상태

| 수정 | 로컬 상태 | 실사용 전 남은 일 |
|---|---|---|
| ① Base 전용 불변 P-256 계정 | 구현·Forge 검증 | 실제 Base의 주소·EntryPoint·프리컴파일·배포/초기화 검증과 독립 감사 |
| ② 상태 기록 USDC 세션 한도·수취인 검사 | `transfer` 경로 구현·경계 테스트 | 실제 USDC 및 사용자 앱·릴레이어 연결 |
| ③ x402 실제 정산 | ERC-1271/EIP-3009를 안전하지 않은 경로로 열지 않음 | 선택한 facilitator가 계정 `transfer`를 받아 정산하는지 종단 간 시험 |
| ④ 가스 지불자·실패 대안 | 위 표로 책임을 정의 | ETH 충전·대납 거절·긴급 철회 운영 경로 구축 |
| ⑤ 기기 상실·탈취 복구·즉시 정지 | 독립 guardian, 48시간 지연, 소유자 회전, 세션 철회 구현·로컬 시험 | Base 앱 연결, 다른 실제 Mac으로 복구·알림·비상 정지 리허설 |
| ⑥ Circle 동결·법률 위험 고지 | 이 문서에 보호 범위와 동결 권한 명시 | 고객 화면·약관 반영, 실제 자금 흐름과 제공 국가별 법률 검토 |

실자금 사용 전에는 계약·통합 독립 보안 감사, 관할권별 법률 검토, 선택한 x402 facilitator와 실제 USDC의 정산·환불 실패 시험, Base 앱 충전·철회 UI, ETH 가스 대안, Circle 동결 시 안내가 필요하다. 회사가 자금을 받거나 이전하는 운영을 하게 되면 법률 판단의 사실관계도 달라진다. 이 설계는 규제 면제 주장을 하지 않는다. EastSea 체인의 합의나 코인 보상은 이 Base USDC 결제 경로의 필수 요소가 아니다.
