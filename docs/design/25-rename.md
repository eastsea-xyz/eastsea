# 25. 이름 바꾸기: Aether → 동해(EastSea), AETH → Doubloon(DBLN) (2026-09-29)

결정: 창업자가 프로젝트 이름을 **동해**로, 코인 이름을 Claude가 새로 짓기로 했다(제안: **Doubloon, 티커 DBLN**, 창업자 최종 확인 대기). 영문 표기는 도메인을 보유한 **EastSea**. 근거: [trademark-2026.md](../research/trademark-2026.md)(Aether·AETH 충돌), [eastsea-2026.md](../research/eastsea-2026.md), [stablecoins-2026.md](../research/stablecoins-2026.md)(코인 이름 충돌 확인). 순서: 상표 출원 → **개명** → 메인넷 → 16석 시험·성능(메인넷에서).

## 단계 (앞 단계가 끝나야 다음)
| 단계 | 무엇을 | 위험 | 호환 |
|---|---|---|---|
| **1. 화면에 보이는 이름** | 앱·확장·웹 문구, README·DISCLAIMER(6개 언어), 문서 제목, 앱 화면의 "Aether"→"EastSea", 코인 문구 "AETH"→코인 이름은 **상수 하나**로 두고 확정 뒤 교체 | 약관 문구가 바뀌므로 `Terms.version` 올려 다시 동의를 받는다(전면 면책 문구는 그대로 유지) | 통신·저장 형식 불변 |
| **2. 앱 이름과 번들 ID** | 앱 표시 이름, DMG 이름, 앱 메뉴, 릴리스 제목. 번들 ID는 **바꾸면 Keychain·업데이트 연속성이 끊기므로** 기존 `com.pipln.aether` 유지 여부를 먼저 결정 | 업데이트 채널(Sparkle 피드 주소)과 서명 정체성 | 번들 ID를 바꾸면 기존 사용자는 새 앱으로 이동해야 함 |
| **3. 서비스·파일 이름** | launchd 이름, 데이터 폴더, 로그, 스크립트 이름 | 실행 중인 테스트넷·설치된 앱의 경로 | 옛 경로를 읽는 이행 코드 |
| **4. 통신 이름 `aether_*`** | RPC 이름, 앱-노드 규약 | 설치된 앱과 노드가 서로 못 알아봄 | **새 이름과 옛 이름을 함께 받는 기간**을 두고 나중에 옛 이름 제거. 메인넷 제네시스는 새 이름으로 시작 |
| **5. 크레이트·컨트랙트 이름** | `aether-*` → 새 이름, `AetherAccount`→ 새 이름 | 컨트랙트는 배포 주소·바이트코드 해시가 바뀜(테스트넷은 종료 예정) | 메인넷 제네시스 전에 |
| **6. 티커** | AETH → DBLN(확정 뒤) | 앱 문구·토큰 표시·거래소 메타데이터 | 1단계에서 상수화해 한 곳만 바꾼다 |
