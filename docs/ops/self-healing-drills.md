# 자가 회복 실기기 점검 (메인넷 전 사람이 한 번씩)

자동 테스트는 순수 판정·시뮬레이션까지만 확인했다. 아래는 **실제 Mac에서 장애를 일으켜 보는** 점검이다. 한 번도 돌린 적 없다(2026-10-03 기준). 설치된 앱(`/Applications`)과 격리된 테스트 데이터로 하고, 돌아가는 테스트넷 노드는 건드리지 않는다. 각 항목은 "하면 / 기대 / 실패하면 볼 곳"이다.

| # | 장애 | 하는 법 | 기대 | 근거 (레드팀 번호, 설계 문서) |
|---|---|---|---|---|
| 1 | 앱을 DMG에서 직접 실행 | DMG를 열고 마운트된 볼륨의 앱을 더블클릭 | 노드·로그인 항목 시작 안 함, 한 문장과 Finder 버튼, 지갑 읽기 화면은 열림 | #10 (`InstallLocation.swift`) |
| 2 | 다운로드 폴더(격리)에서 실행 | 새로 받은 앱을 Downloads에서 실행 | 위와 같음. 실제 App Translocation 경로 형식이 규칙에 걸리는지 확인 | #10 |
| 3 | 업데이트 다운로드 중 네트워크 끊기 | 테스트용 appcast로 업데이트를 시작하고 다운로드 중 Wi-Fi 끄기 | 네트워크 원인으로 기록, 1분→6시간 백오프로 재시도, 촘촘한 반복 없음 | #11 (`UpdateTracker.swift`) |
| 4 | 설치 중 앱 강제 종료 | 설치 단계에서 `kill -9` | 다음 실행에서 실행 중 버전과 대상 버전을 비교해 판정하고 재개 | #11 |

| 8 | 데이터 폴더 전체 삭제 | 데이터 디렉터리를 통째로 지움 | 형제 `node.identity`로 첫 설치로 오인하지 않음 | #5 |
| 9 | 상태 DB 손상 | `state.redb`를 앞부분만 남기고 잘라냄 | `corrupt-<시각>/`으로 옮기고 스냅샷으로 복구, **투표 저널은 건드리지 않음** | #4 |

## 기록 방식
항목마다 날짜·Mac 모델·macOS 버전·결과(통과/실패/관찰)를 이 표 옆에 적는다. 실패는 재현 명령과 로그를 같이 남기고 레드팀 번호로 되돌린다. **한 줄이라도 안 돌렸으면 안 돌렸다고 쓴다.**
